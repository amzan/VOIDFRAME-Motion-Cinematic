# Audio, publishing and delivery
Use actual audio duration, not guessed narration speed. Mark cues in frames, keep music under voice, use owned/licensed VO, music, Foley, ambience. Do not imitate a real speaker without consent. Deliver SRT as separate file if narration exists. For narration in any requested language, use a supplied track or approved TTS service; provide an offline scratch cue sheet if absent. Never upload the film automatically.

Editor defaults: 1920x1080 horizontal or 1080x1920 vertical, 24 fps (30 if requested), 4K optional after performance check. Stage both layouts separately; protect title/subtitle/action from platform UI. Export with official FFmpeg plugin; if missing, PNG sequence and WAV from project or approved audio. For a contiguous sequence named frame000000.png starting at zero, an optional system FFmpeg command is:
`ffmpeg -framerate 24 -start_number 0 -i frame%06d.png -c:v libx264 -crf 18 -pix_fmt yuv420p -movflags +faststart proof.mp4`
Adjust pattern and start number to real output; add audio only when actually present and synchronized. For optional inspection: `ffprobe -v error -show_streams -show_format -of json proof.mp4`. Check frame count/duration tolerance of one frame; inspect sample frames AND actual playback. Audio sample rate 48 kHz and loudness target around -14 LUFS / <= -1 dBTP when appropriate. Record evidence and known limitations. Do not commit renders, user stories, voice recordings, API keys or licensed media to public repository.
