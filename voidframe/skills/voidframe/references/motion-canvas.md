# Motion Canvas implementation
Baseline: Motion Canvas 3.17.2, TypeScript, Vite 5, Node 22. Check installed versions and official API before changing. Starter is a small, original code demo, not a production-grade renderer or finished character library. `npm install`, `npm run check`, `npm start` from copied starter after approval; editor usually at http://localhost:9000. `npm run build` bundles code; it does NOT render an MP4.

Use `makeProject`, `makeScene2D`, JSX or node constructors, `createRef`, `createSignal`, `all`, `chain`, `waitFor`, tween/easing from core. Keep each scene generator deterministic and avoid real-time timers, unseeded randomness, unstable network assets or frame-rate-dependent simulations. Set resolution and FPS in editor Video Settings and persist project metadata. Use duration frames / fps; compare rendered frames to manifest. Read actual installed typings for version-specific methods.

Organize `src/scenes/`, `src/rig/`, `src/motion/`, `src/art/`, `src/camera/`, `src/effects/`. World node contains depth layers, actors and props. Animate each layer's transform at a different rate for parallax; use Camera/Camera.Stage when useful, not both camera and world transforms unintentionally. Use vector paths and locally stored SVG/PNG textures. Build light with gradients, overlays, shadow shapes, masks or supported compositing; avoid assuming real 3D or physically simulated lighting. 2.5D is an illusion of depth via staging and transforms. Use `Path` for authored silhouettes, `Img` for layered assets, `Line` for trails; avoid final art assembled solely from default primitives. Use stable seeded particles. Review opacity/overdraw, large raster assets and memory at target resolution.

Motion Canvas rendering uses browser editor plus Vite backend. Select Video (FFmpeg) exporter in Video Settings, target FPS/resolution/range, audio if present, then Render. The official plugin installs its own FFmpeg dependency. Without GUI automation, provide manual instructions, do not fabricate a headless command. If user permits browser automation, verify UI selectors/version and actual output. PNG sequence is supported; standalone ffmpeg/ffprobe are optional local tools for postprocessing and QA.
